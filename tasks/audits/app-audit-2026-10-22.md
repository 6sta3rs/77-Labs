# Application audit, 22 October 2026

This is an English translation of an internal Polish audit; its findings describe the state of the code on 22 October 2026, BEFORE the fixes shipped in 0.2.2 (see `tasks/audits/audit-2026-10-22.md` for the fix checklist), and it is kept for history.

Scope: frontend code (`src/`), the Tauri supervisor (`src-tauri/src/runtime.rs`), the engine adapters (`scripts/runtime/app/`) and the pinned engine sources (`engine.zip`, unpacked to `.tmp/audit-engine`). The engine was not running during the audit (port 4312 did not respond), so conclusions about UI <-> engine flows come from code analysis, not from clicking through the application.

Checks performed in this session:
- `npm run check`: 0 errors, 0 warnings.
- `npm run test:ui`: all tests PASS.
- Endpoint cross-check (every path called from the frontend vs. the engine routes / adapters / Tauri commands): no missing routes and no method mismatches.
- Codex state on this machine (`ai_tagging.py --status`): signed in through ChatGPT, 3 models (default `gpt-6-luna`).

## 1. Reported bug: an AI provider exists and is signed in, but the model cannot be set

Diagnosis (code): the ChatGPT (Codex) account is **not a provider for "Funkcje AI"** (AI functions).

- `src/lib/settings/pages/AiPage.svelte:334` — `llmRows = rows.filter(r => r.p)`; the ChatGPT row has no `p` (it is not an engine provider), so in the **Funkcje AI** tab "Domyślny model" (Default model) shows "Brak dostawcy" (No provider) and a "Połącz dostawcę" (Connect a provider) button, which sends the user to the tab where ChatGPT is already "Połączony" (Connected). A dead-end loop.
- On the engine side, the functions (dubbing translation, dictation editing, ...) use only the providers from `services/llm_providers.py`. CLI providers (`codex-cli`, `claude-code`) need a bridge from the Electron application (`services/llm_cli.py` reads `VOICESTUDIO_LLM_AGENTS` and `VOICESTUDIO_LLM_AGENT_URL`), which Tauri never sets. So today the ChatGPT account supports **only tagging in the editor**.
- Access to the Codex models itself works: the adapter returns 3 models, so the ChatGPT row editor (the "Model LLM" Select) should show them.

Related bugs in the same place:

1. **No manual model entry in the "Domyślny model" picker** — in `full` mode `ModelPicker.svelte:117` does not render the "Wpisz model ręcznie" (Enter model manually) button. For providers without model listing (Anthropic and others with `transport="sdk"`; the engine returns an empty list for non-OpenAI providers) the picker shows only the model that is already set and it is impossible to choose another one.
2. **"Requires a model -> does not fetch the model list" loop** — providers without a default model (Together, Fireworks, Moonshot, MiniMax, Z.AI, iFLYTEK, Azure, Custom, ...) are `configured=false` until a model is entered (`configuration_error(require_model=True)`). `AiPage.svelte:171 fetchLists()` fetches lists only for `isReady` providers, so in the picker the group is greyed out as "Wymaga konfiguracji" (Requires configuration) and there is no list. Only a roundabout path works: Edit -> "Pobierz listę modeli" (Fetch model list) (the `/models` endpoint uses `require_model=False`).
3. **Claude Code is a dead UI element** — the start tile, "Połącz Claude Code" (Connect Claude Code), the "Do potwierdzenia" (To be confirmed) badge: the engine detects the CLI only through the `VOICESTUDIO_LLM_AGENTS` variable from the Electron shell, so in this application it will always be "Nie wykryto" (Not detected).
4. The list of local providers (Ollama, LM Studio) depends on `localStorage` (`voicestudio.ai.providers.v1`, `AiPage.svelte:107`). A configured but inactive local provider disappears after the browser storage is cleared or in a different window (EXE vs. preview).
5. The "Automatyczne tagowanie AI" (Automatic AI tagging) switch shows "wyłączone" (off) when Codex is not connected, even though `enabled=true` in the settings file (cosmetic).

## 2. Engine and model in memory — why you wait for loading

1. **Two independent idle timers.** Rust stops the process after 5/15/30/60 min ("Utrzymuj silnik po bezczynności" (Keep the engine alive when idle)), but **the engine itself unloads the TTS model after 900 s** (`services/model_manager.py: idle_worker`, `_resolve_idle_timeout`: prefs `idle_timeout_seconds` -> env `OMNIVOICE_IDLE_TIMEOUT_S` -> 900). With a 30/60 min setting the model still disappears after 15 min, and the next generation waits for the weights. The UI description ("Po tym czasie bez generowania silnik zwalnia pamięć" (After this time without generating, the engine frees memory), `EnginePage.svelte:583`) does not match the behaviour.
2. **There is no way to change this time.** `OMNIVOICE_IDLE_TIMEOUT_S` is not in `PERSISTENT_KEYS` (`/system/set-env` rejects it), and `launcher.py:206` removes all `OMNIVOICE_*` variables from the environment at startup. No route writes `idle_timeout_seconds` to prefs.
3. **No "load the model now".** The "Model w pamięci" (Model in memory) card has only "Zwolnij" (Release). The engine has no route that loads the model; `preload_model()` is called once in the lifespan. After an unload (idle or manual) the first synthesis pays the full loading time.
4. **Autostart and preload are hard-coded.** `App.svelte:414` always calls `bootRuntime()` in the desktop application; `runtime.rs:668` always sets `VOICESTUDIO_NEXT_PRELOAD_TTS=1`. There are no settings.
5. Preload is skipped silently when the model terms are not accepted or the weights are missing (`preload_model` in the engine). The startup card simply disappears — the user does not know the model will not be ready. The reason should be shown ("accept the terms in Modele" (Models)).

## 3. Other bugs and elements that may not work

1. **Updates in a copy without the installer.** `tauri.conf.json` has `endpoints: []`; the address is injected only by `npm run desktop:release`. In an EXE from `desktop:build`, "Sprawdź aktualizacje" (Check for updates) ends with a raw plugin error instead of a "this copy does not support updates" message.
2. **One model per provider.** Choosing a "custom" model for one function changes the provider's model globally (an engine limitation, `AiPage.svelte:345`). The toast says so, but the "Własny" (Custom) label suggests something else.
3. **The settings filter** searches only page names, not the content of the settings (documented).
4. **Filtering models by name** (`NON_CHAT` regex, `AiPage.svelte:161`) filters out, among others, everything containing "speech", "tts", "realtime" — e.g. `gpt-4o-realtime` models are hidden, which is fine, but a list without a capability flag may also hide chat models with unusual names; manual entry is the only workaround (and in `full` mode it does not exist — see item 1.1).
5. Untranslated strings in the tools (dictation, automation, transcription, stories): details in section 5.

## 4. Recommendations

### Engine (the settings you asked about)

Place: **Ustawienia -> Silnik -> Stan** (Settings -> Engine -> State), next to "Utrzymuj silnik po bezczynności".

1. **"Uruchamiaj silnik przy starcie aplikacji"** (Start the engine when the application starts) (switch, on by default). Key in `localStorage` (like `voicestudio.engineIdleMinutes`), read in `App.svelte` before `bootRuntime()`. Zero changes in Rust.
2. **"Po uruchomieniu ładuj model głosowy do pamięci"** (After startup, load the voice model into memory) (switch, on by default). A Tauri command `runtime_set_preload(bool)` storing the flag in `Inner`; `start()` sets `VOICESTUDIO_NEXT_PRELOAD_TTS` to `1`/`0`. It takes effect from the next engine start — just like the idle time does now.
3. **"Utrzymuj model w pamięci"** (Keep the model in memory) — simplest: one value shared with "Utrzymuj silnik po bezczynności". The adapter (`system_settings.py`) gets a route `PUT /next/settings/model-idle {seconds}` that writes `prefs.set_("idle_timeout_seconds", …)`; the engine reads it every 30 s without a restart. After the minutes value changes, the frontend calls both (Rust + adapter). The UI description becomes true.
4. **"Załaduj model teraz"** (Load the model now) in the "Model w pamięci" tile: an adapter route `POST /next/model/preload` that runs `asyncio.create_task(backend.preload_model())` (the same function as at startup) and returns `/model/status`. The `EngineStartup.svelte` card already tracks `/model/status`, so progress will show up on its own.
5. When preload is skipped, show the reason (terms not accepted / weights missing) in the startup card or in the model tile, with a link to "Modele".

### AI and keys

1. In the **Funkcje AI** tab, when ChatGPT is the only connected account: instead of "Brak dostawcy", a clear message "Konto ChatGPT obsługuje tylko tagowanie. Funkcje wymagają dostawcy z kluczem API lub lokalnego (Ollama, LM Studio)" (The ChatGPT account supports tagging only. Functions need a provider with an API key or a local one) with an "Dodaj dostawcę" (Add a provider) button.
2. Eventually: a **Codex bridge for functions** — `launcher.py` sets `VOICESTUDIO_LLM_AGENTS=["codex"]` and exposes a local `/complete` based on `codex exec` (the same mechanism as `ai_tagging.run_codex`). Then `codex-cli` becomes a full provider and the ChatGPT account works in all functions. Analogously `claude` for Claude Code (Anthropic terms to be checked).
3. Hide the Claude Code tile until the bridge exists (or show "niedostępne w tej wersji" (unavailable in this version)).
4. `ModelPicker` in `full` mode: add "Wpisz model ręcznie".
5. `fetchLists()`: fetch lists also for providers that lack only a model (key and address are present), and do not grey out their group; in the row status show "Wybierz model" (Choose a model) instead of "Wymaga konfiguracji".
6. Keep the list of "added" local providers in the engine (e.g. `settings_store` key `next.llm.added`) instead of in `localStorage`.

### Updates

- When `endpoints` is empty (a copy without the installer), disable the button and show "Ta kopia nie obsługuje aktualizacji — zainstaluj wersję z instalatora" (This copy does not support updates — install the version from the installer).

## New bugs found live

1. **Speech recognition requires a 2.9 GB download although the turbo model is installed.** The engine has no ASR engine selected (`/engines` -> `asr.active: ""`), so it automatically takes WhisperX, which asks for `Systran/faster-whisper-large-v3`. The installed `deepdml/faster-whisper-large-v3-turbo-ct2` (1.5 GB) is ignored. Effect: `/dictation/readiness?purpose=transcribe` -> `asr_model_missing`; "Mowa na tekst" (Speech to text) (accurate/reference mode), "Rozpoznaj tekst z nagrania" when cloning, and transcription in Dubbing, the Queue and Conversion do not work. It cannot be fixed in the UI: `ModelsPage.rowsFor` links an engine only to the first matching model (large-v3), the turbo row has no "Użyj" (Use) button, and `selectEngine()` never sends the `model_id` that the engine accepts (`POST /engines/select` with `model_id` for faster-whisper). Fix: for faster-whisper-compatible ASR weights add "Użyj" -> `selectEngine('asr','faster-whisper',{model_id})`, and in "Mowa na tekst" show the engine that is actually selected instead of "Wybierz model" (Choose a model).
2. **The running application is older than the repository.** The log of the last start (18:58) has no entry about TTS preload — the `VOICESTUDIO_NEXT_PRELOAD_TTS` gate was not set. Build/install the current EXE, otherwise the changes from the latest commits do not take effect.
3. **The first translation in Dubbing waits ~18 s with no information.** `GET /engines/translation` took 18.3 s on a cold start (the argostranslate import in `translation_engines._probe`), then 0.3–0.7 s. `ProductionWorkspace.translateDubRequest` calls it before every translation and already sets the message "Tłumaczenie segmentów…" (Translating segments…) earlier. Fix: the `engine_catalogue_metadata.py` adapter should also cover `/engines/translation` (response with `import_check=False`), or the UI should show "Przygotowanie silnika tłumaczenia…" (Preparing the translation engine…).
4. **Every request to the engine is two requests.** `request()` in `api.ts` fetches `/next/remote/state` before every path (except `/health` and `/next/*`); `synchronizeRemoteRouting` does not cache the result. The browser network log shows a `remote/state` + actual path pair for every call (e.g. 2 requests/s during 90 s of tracking `/model/status`). Fix: cache for a few seconds and refresh when the connection changes.
5. **The Models page polls `/next/models/jobs` every 1.5 s even when nothing is downloading.** Poll only when a job is active.
6. **Two different "pronunciation dictionaries".** Ustawienia -> Słownik wymowy (Settings -> Pronunciation dictionary) (a form with a language choice, a test) and the "Słownik wymowy" tool from the "Więcej narzędzi" (More tools) menu (a different form: "Rodzaj wymowy" (Pronunciation type) IPA/CMU "bez stosowania" (not applied), language as free text "Polish lub *" (Polish or *)). The same database, two interfaces, different fields. Keep one.
7. **The active TTS engine still "needs verification".** In Modele the OmniVoice row has both an "Aktywny" (Active) badge and a "Sprawdź i użyj" (Check and use) button with the description "Sprawdzenie silnika nastąpi po jawnym wyborze" (The engine is checked after an explicit selection), even though it had just generated a recording. After a successful synthesis the catalogue should mark the active engine as confirmed.
8. **Cold settings reads are slow.** The first `/api/settings/llm-providers` took 2.1 s, `/api/settings/llm-skills` 1.5 s, `/api/settings/performance-profile` 2.8 s; later ones 0.3–0.8 s. The "AI i klucze" (AI and keys) page waits for all five reads at once ("Wczytuję ustawienia z silnika…" (Loading settings from the engine…)). Sections could render as the data arrives.
9. **LLM-dependent tools have no way out.** "Narzędzia audio" (Audio tools) (execution hints, fitting to time), dictation editing and LLM translation in dubbing show "Wybierz model", and the list is empty because `/engines/llm` knows only `openai-compat` and `off`. The message should point to "AI i klucze" and say plainly that a provider with a key, or a local one, is needed.
10. No Hugging Face token (a diagnostics warning). Gated models (e.g. pyannote for speaker separation) will not download; this is worth hinting at next to the "Pobierz" (Download) button of such models.

## What this means for your question about the engine

Measurement: 3.5 s of synthesis vs. ~117 s of weight loading. Every model unload (after 900 s of engine idleness, regardless of the 30/60 min setting) costs about two minutes at the next generation on this machine. The two settings from Part 1 ("load the model after startup" and "keep the model in memory" tied to the engine idle time) plus the "Załaduj model teraz" button solve this without engine changes — it is enough to write `idle_timeout_seconds` to prefs through the adapter.
