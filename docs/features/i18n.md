# Interface languages

The interface is written in Polish; other languages are catalogs next to it. A new language is a folder with one file plus one line in a registry.

## How it works

- **Polish is the source language.** Components call `tr('Polish text')` (`createUiTranslator($uiLanguage)`); the Polish text is also the translation key. Polish needs no catalog.
- **A catalog is `Polish source text -> text in that language`.** English lives in `src/lib/i18n/en/` (12 files merged by `en/index.ts`, about 4,500 keys). `{name}` placeholders must stay the same in every language.
- **Fallback chain** for a language that has not translated a key yet: the language itself, then English, then the Polish source. A partly translated language is therefore usable at any time.
- **Text that is already translated** (for example an English message from the engine) is mapped back to its Polish source through all catalogs and shown in the selected language.
- **The registry** is `src/lib/i18n/languages.ts`: code, name in the language itself, locale for `Intl` (numbers and dates, `tr.locale`), optional `dir: 'rtl'`, the catalog, and `complete: true` for languages that must contain every English key. The picker in Ustawienia → Ogólne ("Język interfejsu") is built from it.
- The choice is stored in `localStorage` under `seventy-seven-labs.ui-language.v1` and sets `<html lang>` and `<html dir>`. It never touches speech settings or the backend.

## Add a language

```powershell
npm run i18n:add -- de "Deutsch" de-DE        # creates src/lib/i18n/<code>/index.ts and registers it (add rtl as a 4th argument for right-to-left)
npm run i18n:missing -- de                     # writes .tmp/i18n/de-missing.json: { "Polish source": "English reference" }
# translate the values into src/lib/i18n/<code>/index.ts (split into several files like en/ when it grows)
npm run i18n:status                            # coverage per language
npm run check ; npm run build ; npm run test:ui
```

`tests/frontend/i18n-languages-check.mjs` (part of `npm run test:ui`) rejects empty values, keys that do not exist in English, changed `{placeholders}`, and a missing key in a language marked `complete`. Set `complete: true` in the registry once a language is fully translated so that it stays that way.

## What a new language does not cover yet

- **Plurals.** `src/lib/i18n/plural.ts` is Polish (one / few / many) and the three Polish forms are translated through the catalog. That works for languages with up to three forms; a language with more (for example Arabic) needs a plural helper based on `Intl.PluralRules`.
- **Right-to-left layout.** `dir: 'rtl'` is set on the document, but the stylesheets still mostly use physical left/right properties (about 105 lines against 13 with logical inline-start/end) and were not adapted.
- **Hard-coded Polish formatting.** A few places format numbers or language names with a fixed `pl-PL` / `pl` instead of the current locale (`engine-installation.ts`, `TranscriptionWorkspace.svelte`, `voice-picker.ts`).
- **Outside the interface.** Messages produced by the Python engine and by the Rust shell are shown in other languages only when their text matches a catalog key (Polish or English); everything else stays as written. Documentation and the installer are not translated.
- **Bundle size.** Catalogs are imported statically in `languages.ts` (about 0.4 MB of text per language before compression). With more than about five languages, load catalogs on demand; `languages.ts` is the only seam to change.

## Where to change things

| What | Where |
| --- | --- |
| Registered languages | `src/lib/i18n/languages.ts` |
| Runtime: translator, fallback, persistence | `src/lib/i18n/index.ts` |
| English catalog | `src/lib/i18n/en/*.ts` |
| Language tools | `scripts/dev/i18n-lang.mjs` (`npm run i18n:status`, `i18n:missing`, `i18n:add`) |
| Tests | `tests/frontend/i18n-check.mjs` (runtime), `i18n-languages-check.mjs` (registry, catalogs, scaffold), `i18n-coverage-check.mjs` (every Polish string in the code has an English key) |
