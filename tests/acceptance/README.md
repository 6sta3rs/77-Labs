# Acceptance scripts

Scripts that drive a real (disposable) engine, a browser or the built EXE. They are not run by CI; most need an engine, weights or the Windows EXE and write their reports under the ignored `.tmp/qa/`. The unit-style tests are in `tests/runtime` and `tests/frontend`; developer tools are in [`tools/`](../../tools/README.md).

| Tool | Purpose | When to run | Called by |
| --- | --- | --- | --- |
| `tests/acceptance/accept_tts_extension.py` | Public-sample acceptance of an installed Kokoro/Chatterbox sidecar using a disposable backend. | Manually after installing a TTS extension. Needs: engine. | nothing (manual) |
| `tests/acceptance/ai-runtime-smoke.py` | Verifies the embedded launcher AI router on a free port with isolated test data. | Manually when changing the AI router. Needs: engine. | nothing (manual) |
| `tests/acceptance/audio-diagnostics-smoke.mjs` | Audio diagnostics smoke against an owned disposable backend (needs VOICE_QA_TOKEN, port 4312). | Manually when changing audio diagnostics. Needs: engine. | nothing (manual) |
| `tests/acceptance/audio_cpp_install_acceptance.py` | Prepared real audio.cpp install/cancel/retry acceptance against owned QA only (requires --run). | Manually when changing audio.cpp installation. Needs: engine, network. | nothing (manual) |
| `tests/acceptance/catalogue_latency_evidence.py` | Read-only hook checking catalogue GETs during two CPU continuation cycles. | Only called from the CPU continuation harness. Needs: engine. | nothing (manual) |
| `tests/acceptance/catalogue_ui_acceptance.py` | Built-UI verification of the catalogue with labelled fixtures; no real backend POST or model. | Manually when changing the engine catalogue UI. Needs: browser. | nothing (manual) |
